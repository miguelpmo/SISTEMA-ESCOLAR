# GUIA COMPLETO — SISTEMA ESCOLAR

## 1. O QUE VOCÊ RECEBEU

ESTA VERSÃO FOI ORGANIZADA PARA SER MAIS SIMPLES DE INSTALAR E MANTER. O VISUAL CONTINUA USANDO O MESMO ARQUIVO `CSS/STYLE.CSS`; NÃO FOI FEITA UMA REFORMULAÇÃO DO LAYOUT.

- `INDEX.HTML`: ESTRUTURA DAS TELAS.
- `CSS/STYLE.CSS`: VISUAL ORIGINAL. MANTENHA ESTE ARQUIVO.
- `JS/APP.JS`: LOGIN, PAINÉIS, CADASTROS, MATRÍCULAS E NOTAS.
- `JS/SUPABASE.JS`: CONEXÃO DO NAVEGADOR COM A CONFIGURAÇÃO PÚBLICA DO SUPABASE.
- `API/CONFIG.JS`: ENTREGA SOMENTE URL E CHAVE PÚBLICA AO NAVEGADOR.
- `API/_SUPABASEADMIN.JS`: CONEXÃO PRIVADA DO SERVIDOR COM O SUPABASE.
- `API/CADASTRAR-USUARIO.JS`: CADASTRO DE PROFESSORES E ALUNOS, RESTRITO A ADMINISTRADOR.
- `API/LOGIN-ALUNO.JS`: LOGIN DO ALUNO USANDO MATRÍCULA.
- `VERCEL.JSON`: CONFIGURAÇÃO DAS FUNÇÕES DA VERCEL.
- `PACKAGE.JSON`: DEPENDÊNCIAS DO PROJETO.
- `SUPABASE/`: ARQUIVOS DE APOIO PARA CONFERIR O BANCO E CONFIGURAR POLÍTICAS DE ACESSO.

## 2. ANTES DE COMEÇAR — FAÇA UMA CÓPIA DE SEGURANÇA

1. NÃO APAGUE O REPOSITÓRIO ANTIGO AINDA.
2. NO GITHUB, ABRA O REPOSITÓRIO ATUAL.
3. BAIXE UMA CÓPIA ZIP OU CRIE UMA BRANCH DE BACKUP.
4. EXTRAIA ESTE NOVO ZIP NO COMPUTADOR.
5. ENVIE O CONTEÚDO DA PASTA `SISTEMA-ESCOLAR-MAIN` PARA A RAIZ DO REPOSITÓRIO GITHUB. A PASTA `INDEX.HTML` DEVE FICAR NA RAIZ, NÃO DENTRO DE OUTRA PASTA COM O MESMO NOME.
6. CONFIRA SE O GITHUB MOSTRA `INDEX.HTML`, `API/`, `CSS/`, `JS/`, `SUPABASE/`, `PACKAGE.JSON` E `VERCEL.JSON`.

## 3. CONFIGURAR O SUPABASE

1. ENTRE EM `HTTPS://SUPABASE.COM/DASHBOARD`.
2. ABRA O PROJETO QUE JÁ GUARDA OS DADOS DO SISTEMA.
3. ENTRE EM `PROJECT SETTINGS` → `API` (OU `DATA API`, CONFORME A VERSÃO DO PAINEL).
4. COPIE A URL DO PROJETO. ELA TEM FORMATO PARECIDO COM `HTTPS://SEU-PROJETO.SUPABASE.CO`.
5. COPIE A CHAVE PÚBLICA `PUBLISHABLE` OU `ANON` DO PROJETO.
6. NÃO COPIE A CHAVE `SERVICE_ROLE` PARA O NAVEGADOR. ELA É PRIVADA E SERÁ CONFIGURADA SOMENTE NA VERCEL.

### CONFERIR AS TABELAS

O SISTEMA ESPERA ESTAS TABELAS NO ESQUEMA `PUBLIC`:

- `PERFIS`: `ID`, `NOME`, `TIPO`, `MATRICULA`.
- `TURMAS`: `ID`, `NOME`, `ANO_LETIVO`.
- `DISCIPLINAS`: `ID`, `NOME`.
- `PROFESSOR_TURMAS`: `PROFESSOR_ID`, `TURMA_ID`, `DISCIPLINA_ID`.
- `MATRICULAS`: `ID`, `ALUNO_ID`, `TURMA_ID`.
- `NOTAS`: `ID` (SE EXISTIR), `MATRICULA_ID`, `DISCIPLINA_ID`, `BIMESTRE`, `NOTA`, `PROFESSOR_ID`.

OS CAMPOS `PERFIS.ID`, `PROFESSOR_TURMAS.PROFESSOR_ID`, `MATRICULAS.ALUNO_ID` E `NOTAS.PROFESSOR_ID` DEVEM SER COMPATÍVEIS COM O UUID DO USUÁRIO DO SUPABASE AUTH. OS IDS DE TURMAS, DISCIPLINAS E MATRÍCULAS SÃO NUMÉRICOS NESTA VERSÃO.

SE O SEU BANCO JÁ EXISTE, NÃO CRIE TABELAS DUPLICADAS. USE `SUPABASE/DIAGNOSTICO.SQL` PARA CONFERIR AS COLUNAS. SE O SEU BANCO TIVER NOMES OU TIPOS DIFERENTES, AJUSTE O CÓDIGO OU O BANCO ANTES DE PUBLICAR.

## 4. CONFIGURAR AS VARIÁVEIS NA VERCEL

1. ENTRE EM `HTTPS://VERCEL.COM`.
2. ABRA O PROJETO CONECTADO AO GITHUB.
3. ENTRE EM `SETTINGS` → `ENVIRONMENT VARIABLES`.
4. CADASTRE AS VARIÁVEIS ABAIXO, UMA POR VEZ.

| NOME | VALOR |
|---|---|
| `SUPABASE_URL` | URL HTTPS DO SEU PROJETO SUPABASE |
| `SUPABASE_ANON_KEY` | CHAVE PÚBLICA `PUBLISHABLE` OU `ANON` |
| `SUPABASE_SERVICE_ROLE_KEY` | CHAVE PRIVADA `SERVICE_ROLE` DO SUPABASE |
| `STUDENT_EMAIL_DOMAIN` | DOMÍNIO INTERNO PARA LOGIN DOS ALUNOS, EX.: `alunos.sistema-escolar.com` |

5. MARQUE OS AMBIENTES `PRODUCTION`, `PREVIEW` E `DEVELOPMENT` SE FOR USAR O SISTEMA EM TODOS ELES.
6. CLIQUE EM `SAVE`.
7. A CHAVE `SERVICE_ROLE` DEVE EXISTIR SOMENTE NAS VARIÁVEIS DA VERCEL. NUNCA COLOQUE ESSA CHAVE EM `JS/`, `INDEX.HTML`, `GITHUB`, PRINTS OU MENSAGENS.

## 5. PUBLICAR A NOVA VERSÃO

1. ENVIE OS ARQUIVOS PARA O GITHUB.
2. ABRA A VERCEL E ENTRE EM `DEPLOYMENTS`.
3. AGUARDE O DEPLOY AUTOMÁTICO OU CLIQUE EM `REDEPLOY`.
4. QUANDO O STATUS FICAR `READY`, ABRA O ENDEREÇO DO SITE.
5. ABRA TAMBÉM `SEU-ENDERECO.vercel.app/API/CONFIG`. A RESPOSTA DEVE MOSTRAR `URL` E `ANONKEY`. ISSO É NORMAL: SÃO DADOS PÚBLICOS. NÃO DEVE APARECER `SERVICE_ROLE`.

## 6. PRIMEIRO ACESSO DO ADMINISTRADOR

O SISTEMA NÃO CRIA UM ADMINISTRADOR AUTOMATICAMENTE. USE UMA CONTA ADMINISTRADORA QUE JÁ EXISTA NO SUPABASE AUTH E TENHA UM REGISTRO CORRESPONDENTE EM `PUBLIC.PERFIS`, COM `TIPO = 'ADMIN'`.

PARA CONFERIR, NO SUPABASE ABRA `SQL EDITOR` E EXECUTE:

```sql
SELECT id, nome, tipo, matricula
FROM public.perfis
WHERE tipo = 'admin';
```

SE NÃO RETORNAR NENHUM ADMINISTRADOR, NÃO TENTE RESOLVER COLOCANDO UMA CHAVE PRIVADA NO NAVEGADOR. CRIE/CONFIRME A CONTA COM SEGURANÇA NO SUPABASE E VINCULE O PERFIL CORRETO. A CONTA AUTH E O ID DA LINHA EM `PERFIS` PRECISAM SER O MESMO UUID.

## 7. COMO USAR O SISTEMA

### ADMINISTRADOR

1. ENTRE COM A CONTA ADMINISTRADORA.
2. NA ABA `USUÁRIOS`, CADASTRE PROFESSORES E ALUNOS.
3. PARA PROFESSOR, INFORME UM E-MAIL VÁLIDO.
4. PARA ALUNO, INFORME A MATRÍCULA. O SISTEMA MONTA O E-MAIL INTERNO USANDO `STUDENT_EMAIL_DOMAIN`.
5. NA ABA `TURMAS`, CRIE A TURMA E INFORME O ANO LETIVO.
6. NA ABA `DISCIPLINAS`, CADASTRE AS MATÉRIAS.
7. NA ABA `MATRÍCULAS`, ESCOLHA O ALUNO E A TURMA.
8. NA ABA `ATRIBUIR PROFESSOR`, ESCOLHA PROFESSOR, TURMA E DISCIPLINA.
9. NA ABA `BOLETINS`, CONSULTE AS NOTAS LANÇADAS.

### PROFESSOR

1. ENTRE COM O E-MAIL E A SENHA CADASTRADOS PELO ADMINISTRADOR.
2. ESCOLHA A TURMA.
3. ESCOLHA UMA DAS DISCIPLINAS ATRIBUÍDAS ÀQUELA TURMA.
4. ESCOLHA O BIMESTRE.
5. DIGITE AS NOTAS DE 0 A 10.
6. CLIQUE EM `SALVAR NOTAS`.

A LISTA DE DISCIPLINAS MUDA CONFORME A TURMA ESCOLHIDA. ISSO EVITA SELECIONAR UMA DISCIPLINA QUE NÃO FOI ATRIBUÍDA ÀQUELA TURMA.

### ALUNO

1. NO CAMPO DE LOGIN, DIGITE A MATRÍCULA.
2. INFORME A SENHA DEFINIDA NO CADASTRO.
3. O SISTEMA ABRE O BOLETIM DO PRÓPRIO ALUNO.
4. A MÉDIA PARCIAL É CALCULADA COM OS BIMESTRES QUE JÁ TÊM NOTA. BIMESTRES SEM NOTA NÃO ENTRAM NO CÁLCULO.

## 8. POLÍTICAS DE SEGURANÇA (RLS)

O SUPABASE DEVE TER RLS ATIVO E POLÍTICAS ADEQUADAS. O ARQUIVO `SUPABASE/POLITICAS_RLS.sql` É UM MODELO PARA A ESTRUTURA DE TABELAS DESCRITA NESTE GUIA.

ANTES DE EXECUTAR:
1. FAÇA BACKUP DO BANCO.
2. CONFIRME OS NOMES E TIPOS DAS COLUNAS COM `DIAGNOSTICO.SQL`.
3. LEIA O ARQUIVO SQL INTEIRO.
4. EXECUTE PRIMEIRO EM UM PROJETO DE TESTE, SE POSSÍVEL.
5. NÃO DESATIVE RLS PARA “FAZER FUNCIONAR”. ISSO PODE EXPOR DADOS DE ALUNOS.

SE O BANCO JÁ POSSUI POLÍTICAS, REVISE-AS COM QUEM ADMINISTRA O SUPABASE ANTES DE SUBSTITUIR OU ADICIONAR OUTRAS.

## 10. ERROS COMUNS

**“CONFIGURE SUPABASE_URL...”**
- CONFIRA AS VARIÁVEIS DA VERCEL.
- CONFIRA SE NÃO HÁ ESPAÇOS ANTES OU DEPOIS DOS VALORES.
- FAÇA UM NOVO DEPLOY DEPOIS DE SALVAR AS VARIÁVEIS.

**“INVALID API KEY” OU ERRO DE CONEXÃO**
- CONFIRA SE A CHAVE PÚBLICA É DO MESMO PROJETO DA URL.
- NÃO USE A CHAVE SERVICE_ROLE NO CAMPO `SUPABASE_ANON_KEY`.

**“PERMISSION DENIED”, “RLS” OU “ROW LEVEL SECURITY”**
- CONFIRA AS POLÍTICAS RLS E O TIPO DO USUÁRIO.
- NÃO RESOLVA DESATIVANDO A SEGURANÇA DO BANCO.

**“RELATION DOES NOT EXIST”**
- A TABELA ESTÁ COM NOME DIFERENTE OU NÃO EXISTE NO ESQUEMA `PUBLIC`.

**“COLUMN DOES NOT EXIST”**
- UMA COLUNA DO BANCO TEM NOME DIFERENTE DO ESPERADO. COMPARE COM A LISTA DE TABELAS DESTE GUIA.

**ALUNO NÃO CONSEGUE ENTRAR**
- CONFIRA SE `PERFIS.MATRICULA` É IGUAL À MATRÍCULA DIGITADA.
- CONFIRA SE O E-MAIL INTERNO FOI CRIADO COM O MESMO `STUDENT_EMAIL_DOMAIN`.
- CONFIRA SE O TIPO DO PERFIL É `ALUNO`.

**PROFESSOR NÃO VÊ TURMA OU DISCIPLINA**
- CONFIRA SE EXISTE UM REGISTRO EM `PROFESSOR_TURMAS` COM O UUID DO PROFESSOR, ID DA TURMA E ID DA DISCIPLINA.

## 11. OBSERVAÇÕES IMPORTANTES

- O CSS ORIGINAL FOI PRESERVADO. SE QUISER MUDAR O VISUAL, FAÇA ISSO SEPARADAMENTE EM `CSS/STYLE.CSS`.
- A CHAVE PÚBLICA DO SUPABASE PODE SER USADA NO NAVEGADOR, MAS A `SERVICE_ROLE` É SECRETA.
- A PROTEÇÃO REAL DOS DADOS DEPENDE DAS POLÍTICAS RLS DO BANCO. VALIDAÇÕES NO JAVASCRIPT MELHORAM A EXPERIÊNCIA, MAS NÃO SUBSTITUEM A SEGURANÇA DO SERVIDOR/BANCO.
- O PROJETO NÃO FOI TESTADO CONTRA O SEU BANCO REMOTO. FAÇA OS TESTES DESTA LISTA ANTES DE USAR COM DADOS REAIS.
- NUNCA ENVIE SENHAS, TOKENS OU CHAVES PRIVADAS PARA PEDIR AJUDA. ENVIE SOMENTE A MENSAGEM DO ERRO, SEM DADOS SECRETOS.
